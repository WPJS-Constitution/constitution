## Versioning rule

A Topic starts from its BASE snapshot. Meaningful checked-in changes are recorded in Git history with a short explanation of why and what changed. When a Topic is closed, it is assigned to the next Constitution edition. Every Topic must have a matching version before an edition is assembled; unchanged Topics are carried forward.

The Master Record Index tracks each Topic’s latest snapshot and status. An edition index lists the Topics included in that edition; its version number is implicit in the edition index.

## Approval status

Working material in this repository is not automatically adopted. Topic closure, assembling an edition, stakeholder approval, and formal adoption are distinct steps and must be recorded as such.

The number and formal approval process for the first Constitution edition have not yet been settled.
